# AGENTS.md — mason

## Overview

mason is a headless, always-on agent backend — one deployment is one specialized bot, built on `@earendil-works/pi-durable`, `@earendil-works/pi-env` and `@earendil-works/chord`, with an event-hook system — and interfaces attach to it: Telegram is the first interface. The web app in this repository is not one of them: it is the operator panel, a control plane an operator administers the deployment from, and it cannot speak.

Where a change goes is [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md); the product goal, contracts and milestone specifications are [`docs/SPEC.md`](docs/SPEC.md). Read both before writing code.

The agent lives in `~/.mason/`, in two halves: `agent/` (mounted into the tool machine — `profile.md` is who it works for, agent-managed and always resident; `log/YYYY-MM-DD.md` holds dated facts one per line; `skills/` holds its own instructions; `workspace/` is where it works; `.git` is its memory's history) and `service/` (never a path inside the tool machine — `soul.md` is the first section of its system prompt, `integrations.json` is the services it reaches — each with an MCP endpoint that lends the bot tools, a `connector` block that says what it may do on its socket, or both — and `config.json` holds the token hashes (each with its grants), the session key and the connector credentials, while `data/` is the transcript, the hook state and the attachment store). In the repo, `skills/` is what mason ships — `skills/ocr/SKILL.md` says when to read a page with `indra-ocr`, which is in the tool machine's image — and it is copied into `agent/skills/` on first boot, so a personal skill of the same name wins and the index has one root. A skill mason stops shipping is withdrawn unless somebody edited it. `src/server/house.ts` owns that layout; `MASON_HOME` relocates the home that every reader and writer resolves, and the runtime's `houseHome` option is where it is created — tests point both at a temporary directory, which is how they stay out of the real home. A home from before the split is refused at boot until `npm run doctor -- migrate` has moved it, and the same command is what stamps grants onto credentials written before the panel.

Services attach to mason as **connectors** (`docs/CONNECTOR-PROTOCOL.md`, `packages/protocol`): an external process with any combination of a *user* face (it carries people's words and the agent's replies), a *tools* face (MCP over Streamable HTTP), and an *events* face (a fire). It opens one JSON-RPC WebSocket at `/api/connector`, and `src/server/connector.ts` is mason's end of it — the handshake, admission, the state mirrors, the reply outbox and the agent's budgets. The agent reaches a reader through exactly one call, `reply`: it targets the turn's origin (the connector that carried the words) and never names a vendor's tool. No prompt names one either.

Tools are two things, and neither is a prompt. A service's tools face is a **catalog** the agent asks at the moment of the
call (`mcp_search`, `mcp_describe`, `mcp_call`, script-only), so a server that restarts or redeploys moves nothing the
prompt is built from; and one `beforeTool` hook is the **permission gateway** in front of every direct and nested call,
deciding from the tool's `dev.mason/approval` marker inside the operator's ceiling and asking a person when it must
(`docs/SPEC.md` §4.1e, `docs/adr/0010-tools-are-live-and-every-call-is-gated.md`).

The web app in this repository is the **operator panel** (`src/web/admin/`, `src/server/admin.ts`), served by mason at `/` and `/admin`; [`docs/adr/0011-the-panel-is-a-control-plane.md`](docs/adr/0011-the-panel-is-a-control-plane.md) says why, and [`docs/UI-PLAN.md`](docs/UI-PLAN.md) keeps the record of the apiary port the widget card came from. **A device is sent the reader's transcript, never the conversation:** `src/server/projection.ts` derives `transcript` / `queued` / `agentStatus` from the durable view, and reasoning, tool calls, tool arguments and tool output do not cross with it (`test/projection.test.ts` pins both halves). The raw entries are a separate area of the same answer, `src/server/trace.ts`, sent only to a device the operator granted `trace` (`test/panel.test.ts` pins the refusal). Add a new user-facing surface by naming it in the projection first — a new tool or entry kind is invisible until the whitelist says otherwise. Every panel area is gated in `src/server/admin.ts` by a grant from `src/shared/admin.ts`; a new route without a `requireGrant` is unauthenticated by omission.

## Non-Negotiable Rules

1. **Do NOT touch `apiary`.** This project is standalone; apiary integrates with it rather than replacing it (`docs/adr/0004`).
2. **`@earendil-works/*` are ordinary dependencies, pinned in `package.json`.** There is no submodule and no `vendor/`:
   the pin `f321e5bdd` turned out to carry no fleet patches (#113), the packages are published, and the `pi-env` daemon
   ships inside `@earendil-works/pi-env` for eight platforms. Bump a version in `package.json`, never a commit in a
   submodule. `tsconfig.json`'s `paths` map went with it (#122): the compiler resolves the published types.
   - `CopilotKit/OpenIntelligentUI` is **not** a dependency: the parts this client needed were adapted into `src/web/`
     (`open-genui-content.ts`, `frame-content.ts`, `websandbox-loader.ts`, `SandboxedUiCard.tsx`, and the design-system
     constants in `design-system.ts`, MIT, pin `8391a94`). Do not add it back as a clone.
3. **Do NOT look for `pi-client`, `pi-server`, or `pi-protocol`.** Upstream `pi` deleted those packages in commit `7472cda` because `@earendil-works/chord` (`createHost`, `remote`, `method`, `acceptWebSockets`, `webSocketLink`) now provides the official RPC + live-state replication layer directly over WebSocket.
4. **Always split Harness vs. Tool Execution via `@earendil-works/pi-env`:**
   - Never use `NodeExecutionEnv` directly in the agent harness when `pi-env` is available.
   - Connect `RemoteExecutionEnv` (or `LocalExecutionEnv`) to a `Connection` running `localDaemon()` (the binary ships in `@earendil-works/pi-env`), or an SSH target when configured.
5. **Run TypeScript directly from source on Node 22:**
   - Use `node --experimental-strip-types ...` for all server entrypoints and tests. There is no `--conditions=source`
     any more: it made a published package resolve to `src/`, which is not in its tarball.
6. **Every way in goes through a credential check.** The Chord socket and `/api/*` are the owner's: a token (hashed in `~/.mason/config.json`), the `HttpOnly` session cookie it is spent into, plus an `Origin` that is ours or absent (`src/server/auth.ts`). One more door is outside that gate on purpose and it is not a way to speak as the owner: the connector's own door — `/api/connector` for the socket and `/api/connector/attachments/<contentId>` for bytes — which is authenticated as **the connector** by a credential mason issued for that entry (`src/server/connectors.ts`), read from `Authorization: Bearer` on every upgrade, so a revoke lands on the next connection. A connector credential opens those two paths and nothing else. The signed event door (`POST /api/events/<integration>` and its HMAC trigger secret) is gone (#104): nothing accepts work there, and an entry that still names a `trigger` refuses the boot until `npm run doctor -- migrate` removes it. `/api/health` is the only path that answers without a credential, and it answers one word. A new entry point — another route, another socket, another tool that reaches the network — is unauthenticated until it calls `authenticate` or `authenticateConnector`, and the default answer is no. Responses carry the security headers from `main.ts` (CSP, `no-referrer`, `frame-ancestors 'none'`); a new route gets them for free and must not widen them.
7. **The permission gateway is not optional, and neither is the catalog.** Every tool call — a model's own call and a
   script's nested one — passes `src/server/permissions.ts` before its intent is committed; a new tool is gated by
   existing rather than by being wrapped, and its name is allowed unless the gateway has a rule that says otherwise. No
   MCP tool schema may enter the registry: the surface is `mcp_search`/`mcp_describe`/`mcp_call` and the live catalog
   behind them, because a tool that appears mid-conversation would re-price the prompt prefix. A new approval path must
   keep the answer durable in the transcript (`app.permission`, `app.permission-answer`), the first answer final, and
   `stop` able to end the wait — and it must never let a marker waive an operator's rule.
8. **Least privilege after the door.** The agent's state is `~/.mason/service/data` (home `0700`, files `0600`; `MASON_DATA` overrides) — never `.data` in the cwd, and never inside `agent/`, which the tool machine mounts. An event delivery is capped at 256 KiB and 6 *fires* a minute per integration, the same limiter keyed by the sender — so two integrations firing one hook are two budgets, and the hook's own minute is untouched; a small JSON write to `/api/join` is capped at 32 KiB. A command has a budget of its own beside it, keyed `command:<integration>` where the fire's is `integration:<integration>`: six commands a minute, charged only for a command mason will act on (an undeclared or malformed word spends nothing), so a sender that spent its fire minute can still `/stop` the turn those fires started. A connector's socket budgets each class separately per connector — submissions (60), fires (6), controls (6, with `stop` in a class of its own) and attachments (30) — and an upload is capped at `attachmentBytes` (25 MiB, advertised at the handshake), expiring after `attachmentTtlMs` (a day) and scoped to the connector that posted it. Every refusal names `retryAfterMs`. The `pi-env` daemon starts through `env -i` with an allowlist (`PATH`, `HOME`, `USER`, `LOGNAME`, `SHELL`, `LANG`, `LC_ALL`, `TZ`, `TMPDIR`), so a tool cannot read the server's environment: new configuration belongs in a file, not in an exported variable (`src/server/limits.ts`, `src/server/env.ts`).

## Commands (inside `devenv shell` or via `devenv shell -- ...`)

- `devenv shell -- setup` (or `bash scripts/setup.sh`) — the whole first-time setup: the root install, then `build:packages`. One recipe, run by the dev shell and by CI, so a fresh clone and a green run cannot drift apart.
- `npm install` — installs everything, `@earendil-works/*` included, from npm. Nothing to link and nothing to repair.
- `npm run dev` — starts the durable agent + Chord WebSocket + HTTP server (`src/server/main.ts`).
- `npm run build:web` — bundles the operator panel (`src/web/admin/main.tsx` -> `dist/web/admin.js` + `admin.css`) using `esbuild`.
- `npm test` — runs the test suite (`node --experimental-strip-types --test test/*.test.ts`), after `build:packages`, because the tests import the two packages from `dist`. `npm run test:packages` is the other suite: `packages/protocol` and `packages/connector` (with `--experimental-sqlite`, because the reference store is one SQLite file), and CI runs both.
- `npm run build:packages` — compiles `packages/*` to `dist/` with `tsc`, protocol first. `tsconfig.packages.json` keeps imports written as `./x.ts` and `rewriteRelativeImportExtensions` turns them into `./x.js` on emit, so the same source serves `--experimental-strip-types` in tests and plain `node` in a consumer.
- `npm run prove:connector` — packs both packages, installs the tarballs into an empty temporary project outside the tree, and runs the published conformance suite there with plain `node`. It fails if a package ships a `.ts` file, because a consumer's Node will not strip types inside `node_modules`. It writes nothing into the repository except the gitignored `packages/*/dist` it packs.
- `npm run lint` — biome over `src/`, `test/`, `scripts/`, `evals/` and `packages/` (`node scripts/biome.mjs check .`); `lint:write` applies the fixes. The version is pinned in `package.json` and used unchanged in CI, which is why `.npmrc` asks npm for the musl build — a glibc-linked binary does not start on NixOS — and `scripts/biome.mjs` points the shim at it. `biome.json` takes no comments: with one in it, 2.3.5 sees a second root and refuses the vendored one, so the reasoning lives here (`useExhaustiveDependencies` is off for `src/web/**` because completing a dependency array is a behaviour change in a client this repo has no DOM test for, and CSS is out because the panel and widget sheets are hand-written).
- `npm run typecheck` — the compiler over `src/`, `test/`, `scripts/` and `packages/` (`tsc --noEmit -p tsconfig.json`). `typescript` is a dev dependency, because the suite runs with `--experimental-strip-types`, which erases types without reading them. CI (`.github/workflows/ci.yml`) runs `setup`, the linter, this, the web build and the suite on every push to `main` and every pull request. There is no Rust step: the daemon is a published binary.
- `npm run gen:surface` — renders `docs/SURFACE.md` from the code: every HTTP route and the grant that guards it, the extensions a boot installs, the budgets. `gen:surface:check` fails on a stale or hand-edited copy, and on a route literal with no `requireGrant`; `npm run check:docs` holds each document to its ceiling in `docs/doc-budgets.json` (`docs/AGENTS.md`), and `npm run check:code` holds each area of code to its ceiling in `docs/code-budgets.json`. CI runs them beside the typecheck.
- `npm run eval` — runs the five behaviour scenarios against one model (`evals/run.ts`, default `opencode-go/deepseek-v4.1-flash`), writing traces to `.data/evals/`; flags, cost and scenario shape in `evals/README.md`. It costs real tokens: run it only when asked.
- `npm run eval:judge -- <results-dir>` — scores stored eval traces on message quality against `evals/rubric.md` (`evals/judge.ts`, default judge `ollama/bonsai-2:27b`).
- `npm run token -- list | add --label <name> [--grants a,b] | grants <id> a,b | revoke <id>` — the credentials that may talk to the server (`scripts/token.ts`). A fresh home mints a `browser` token on first start and logs the pairing link; `add` prints one for a new device, with `conversation` unless `--grants` says more. The grants are the panel's powers (`conversation`, `trace`, `admin`, `approve`); the server reads the config per request, so a revoke or a narrowed grant lands immediately, without a restart.
- `npm run doctor -- migrate` — the one command that moves a home forward (`scripts/doctor.ts`, `src/server/house.ts`): a pre-split home into `agent/` and `service/`, and every credential written before grants onto `conversation`, `admin` and `approve` — what the console it replaced could do, and never `trace`. It is one-way and idempotent, and it never runs on boot: a server that rewrote the operator's files on start would be a server that edits his home. A boot that finds an ungranted credential says so once and points here.
- `npm run connector -- list | add <connector> [--replace] | revoke <id>` — the credential a connector opens its socket with (`scripts/connector.ts`). The credential is printed once and stored as a hash in `service/config.json`, beside the tokens and read on every upgrade, so a revoke lands on the next connection rather than the next restart. The grant is the entry's `connector` block in `service/integrations.json`: faces, the one `user.owner` actor (whose words are the owner's, and who may answer that connector's permission requests), conversations, event kinds, state scopes, `trustMarkers`, the `policy` rules (`allow`/`ask`/`deny`, each a tool name or `*`) and the entry's `commands`. A credential for an entry with no `connector` block is refused — it would open a socket with nothing on it.
- `npm run integration -- add <name> --url <mcp-url> --description <line> [--replace] | remove <name> | enable <name> | disable <name> | list` — the services the agent reaches (`scripts/integration.ts`, `src/server/integrations.ts`), in `service/integrations.json`. An entry may carry a tools face (an MCP endpoint over Streamable HTTP, with the one line the model is told about it) and a `connector` grant. A fresh `add` switches it on, while a `--replace` moves the endpoint and leaves the switch and the grant as they were. There is no trigger face any more (#104): a service wakes mason with `mason/fire` over the connector's socket, and what that socket may spend — the `kind` → hook map, the control vocabulary (`connector.commands`, out of the closed set `stop`, `compact`, `clear`, `status`), the state scopes and the approval policy — is its grant, edited on the panel's connectors page or written into the file by hand. The file is read once at boot, so a change is a restart, and it says so. An integration the boot cannot reach loses its tools and says why in `/api/integrations`, unless it is `required` — then the boot refuses.
